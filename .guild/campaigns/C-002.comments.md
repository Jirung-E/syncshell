# 예광탄 실행 계획

## 목표
선택한 스택(Rust + egui + portable-pty + alacritty_terminal + OSC 7)으로
**탐색기 ↔ 터미널 양방향 동기화가 끝에서 끝까지 실제로 성립하는지**를 최소 코드로 증명한다.
동시에 이후 DEV 백로그가 딛고 설 하중 지지 구조를 처음부터 옳게 세운다.
예광탄은 프로토타입과 달리 **버리지 않고 살을 붙여나가는 골격**이다.

## 실행 순서 (의존성 순)
1. **DEV-004 — 헤드리스 cwd 스파이크.** UI 한 줄 쓰기 전에 가장 위험한 가설부터.
   OSC 7을 셸 프로파일 안 건드리고 주입하는 방법을 확정한다. 이 코드는 버린다.
2. **TR-001 — workspace + 좌우 2분할 빈 창.** 골격만.
3. **TR-002 / TR-003 — 터미널 최소 렌더 / 파일 목록.** 둘 다 TR-001에만 의존하므로
   병렬 진행 가능.
4. **TR-004 — OSC 7 cwd 추적 실장.** DEV-004 결론 + TR-002(PTY 스트림) 위에서.
5. **TR-005 — 양방향 동기화 연결.** 예광탄이 관통하는 지점. 앞 네 조각을 SyncState로 묶는다.
6. **TR-006 — 검증 및 회고.** 30분 이상 실사용 후 틀린 가정을 기록하고 DEV 백로그 재조정.

## 처음부터 지킬 아키텍처 약속
**규칙 참조: `architecture`** (`openguild rule show architecture`)

core/UI 분리, CJK 폭 2 처리, 저장 위치 단일화, OSC 7 우선 — 예광탄에 국한된 게
아니라 프로젝트 전체를 관통하는 불변식이라 별도 길드 규칙으로 관리한다.
이 계획에 중복 기술하지 않는다.

## 검증 게이트 (예광탄을 쏘는 진짜 이유)
- **egui 셀 그리드 렌더러 성능** — TR-006에서 대량 출력 체감으로 검증. 실패 시 스택 재검토.
- **OSC 7 주입 실전 내구성** — DEV-004 + TR-006. 커스텀 프롬프트/중첩 셸/빠른 연속 cd.
- **동기화 제품 가설** — 항상 켜진 동기화가 편한가, 토글이 필수인가.
- 콜드 스타트 시간 — egui 선택의 근거였으므로 숫자로 확인.

## 완료 정의
이 캠페인의 체크리스트 7개가 전부 충족되면 예광탄 완료.

## 예광탄 이후
TR-006 회고 결론으로 C-001(1단계 DEV 백로그)을 재조정한다.
2단계(WSL)·3단계(Linux/macOS)는 예광탄이 아키텍처를 증명하기 전까지 상세화하지 않는다 —
아직 검증 안 된 가정 위에 상세 퀘스트를 쌓지 않기 위함.
