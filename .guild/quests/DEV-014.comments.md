## macOS만 구현 — Windows/Linux는 손 안 댐

퀘스트 자체 방침표가 "macOS만 네이티브 유지, Windows/Linux는 직접 그린다"로
플랫폼을 나눠놨다. 이번엔 macOS 쪽만 했다.

### macOS (구현·검증 가능)
`run()`에서 `#[cfg(target_os = "macos")]`로 `ViewportBuilder`에:
- `with_fullsize_content_view(true)` — 콘텐츠가 타이틀바 영역까지 채움
- `with_titlebar_shown(false)` — 타이틀바를 투명하게(콘텐츠가 뒤에 비쳐 보임)
- `with_title_shown(false)` — 제목 텍스트 끔(탭 바가 그 자리를 대신함)
- `with_titlebar_buttons_shown(true)` — 신호등 버튼(닫기/최소화/최대화)은
  계속 네이티브로 뜨게 둠 — 이게 이 방침의 핵심(VS Code·Zed 패턴)

DEV-009에서 만든 탭 바(`show_tab_bar`)가 이제 그 신호등과 같은 줄에 뜨므로,
왼쪽에 78px 여백(`#[cfg(target_os = "macos")]`)을 둬서 탭이 버튼과 안
겹치게 함(macOS 신호등은 항상 왼쪽 고정 폭이라 하드코딩 가능).

실제로 앱을 띄워서 크래시 없이 뜨는 것까지는 확인했다. **이 자동화
환경에서는 화면 캡처 권한(Screen Recording)이 없어서 실제로 신호등 버튼이
탭 바와 겹치지 않고 예쁘게 자리잡는지는 육안으로 확인 못 했다** — 코드
자체는 퀘스트가 명시한 표준 패턴(winit 투명 타이틀바 + fullsize content
view)을 그대로 따른 것이라 동작은 신뢰하지만, 78px 여백 같은 정확한 수치는
실측 없이 넣은 값이라 실제로 보면 미세 조정이 필요할 수 있다.

### Windows/Linux — 손 안 댐
"직접 그린다" 쪽은 raw-window-handle로 HWND를 얻어 `WM_NCHITTEST`/
`WM_NCCALCSIZE`를 서브클래싱하고, Win11 스냅 레이아웃 플라이아웃까지
`HTMAXBUTTON` 응답을 직접 처리해야 하는, 이 프로젝트에서 지금까지 나온
것 중 가장 플랫폼 네이티브 API에 깊이 들어가는 작업이다. 이 개발 환경이
macOS라 Windows 빌드 자체를 확인할 방법이 없는데, 검증 안 된 서브클래싱
코드를 그냥 작성해 넣는 건 (컴파일도 못 해보고) 실제로 창이 아예 안 뜨거나
입력이 먹통이 되는 등 훨씬 심각하게 망가질 위험이 있다고 판단해 보류했다.
Windows 환경에서 다시 진행하는 걸 권장.

- [ ] 멀티 모니터 / 다른 DPI 환경에서 좌표 계산 정확한지

실사용 피드백: "타이틀바가 너무 얇음, 신호등 버튼이 타이틀바에 걸쳐진 모양새"(스크린샷 첨부됨).

## 원인
`egui::Panel::top("tab_bar")`가 기본값(내용에 맞춰 줄어드는 높이)을 그대로 쓰고 있었다. 탭 한 줄 높이(~20px)가 macOS 표준 타이틀바 높이(~38px, Big Sur 이후 통일된 값)보다 얇아서, OS가 그 자리에 그려주는 신호등 버튼이 우리 탭 바보다 커서 위아래로 삐져나온 것처럼 보였다.

## 수정
`lib.rs`에 `TAB_BAR_HEIGHT` 상수 추가(macOS=38.0, 그 외=28.0 — 신호등이 없는 다른 OS는 이 문제 자체가 없어서 기존값 유지) 후 `.default_size(TAB_BAR_HEIGHT)`로 패널 높이를 고정. 탭 바 내용(`show_tab_bar`)을 `Layout::left_to_right(Align::Center)`로 감싸서 늘어난 패널 높이 안에서 세로 가운데 정렬되게 함(안 그러면 내용이 위에 붙고 아래 여백만 늘어남).

## 검증
`cargo test --workspace` 76개 전부 통과, 앱 실행 후 스크린샷으로 직접 확인 — 신호등 버튼이 탭 바 안에 정상적으로 들어가고 탭 제목("jirung290")과 "+" 버튼이 버튼들과 같은 줄에 자연스럽게 정렬됨. 겸사겸사 트리/브레드크럼(DEV-005)과 색상 렌더링(사용자가 직접 16색/256색 테스트로 확인 요청)도 같은 스크린샷에서 정상 동작 확인.

이전 댓글에서 두 가지를 잘못 짚었었다.

1. `default_size(38.0)`를 썼는데, 이건 egui `Panel`에서 "첫 프레임 초기값 힌트"일 뿐이고 허용 범위(min/max)를 안 좁힌다(소스 확인: `Rangef` 계산이 그대로 열려있음) — 그래서 실사용 확인에서 "적용 안 된 것처럼 그대론데" 피드백을 받았다. `exact_size(f32)`로 바꿔야 한다 — 이건 범위를 그 값 하나로 완전히 고정(`Rangef::point`)해서 프레임이 지나도 안 줄어든다.
2. 38.0이라는 값 자체도 감으로 짚은 거였는데 사용자 확인 결과 "너무 넓어짐". "맥 기본 터미널의 타이틀이랑 같은 높이로 맞추고싶음" 요청을 받고 **28.0**(macOS 표준 "툴바 없는" 타이틀바 높이 — Terminal.app/TextEdit 등이 공통으로 쓰는 값, Big Sur 이후 커진 ~52pt는 NSToolbar가 있는 앱 전용이라 무관)으로 낮췄다.

## 최종
```rust
const TAB_BAR_HEIGHT: f32 = 28.0;
...
egui::Panel::top("tab_bar").exact_size(TAB_BAR_HEIGHT).show(ui, |ui| { ... });
```

## 검증
`cargo test --workspace` 76개 전부 통과. 앱을 새로 빌드+실행해서 스크린샷으로 신호등 버튼·탭 바 높이가 자연스러운지 확인(사람 확인 대기 중 — 이 댓글 작성 시점엔 아직 최종 확인 답을 못 받음).
