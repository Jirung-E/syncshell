## 선택·복사 구현 (이 퀘스트 범위 중 일부 — IME는 2차 패스)

사용자가 이전에 "출력 내용 복사도 안되듯"이라고 지적했던 부분. 붙여넣기는 되는데
복사는 안 되는 반쪽 상태였다.

## 구현

선택 상태 자체는 `alacritty_terminal`의 `Selection`이 들고 있다 — 스크롤·리사이즈
시 좌표 보정, 단어/줄 경계 확장, 텍스트 추출(`selection_to_string()`)까지 전부
제공한다. 우리가 한 건 화면 좌표를 셀 좌표로 바꿔 넘기고, 선택 영역을 그리는 것.

- **드래그 선택** (`SelectionType::Simple`)
- **더블클릭=단어** (`Semantic`), **트리플클릭=줄** (`Lines`)
  — egui는 트리플클릭도 `double_clicked()`를 true로 보고하므로 트리플을 먼저 본다
- **드래그로 화면 밖까지** — 위아래로 끌면 스크롤백이 따라 움직인다
- **선택 영역 렌더링**: 전경/배경 반전. 선택색을 따로 두면 그 위 글자색에 따라
  안 보이는 조합이 생기는데, 반전은 원래 대비를 그대로 유지해서 어떤 배색에서도 읽힌다
- **타이핑하면 선택 해제** — 선택해둔 채 명령을 치면 화면이 반전된 채 남아 헷갈린다

## Ctrl+C 라우팅

`Ctrl+Shift+C`는 항상 복사(리눅스 터미널 관례). `Ctrl+C`는 **선택이 있으면 복사,
없으면 인터럽트(0x03)** — Windows Terminal과 같은 규칙이다. 무조건 복사로 바꾸면
실행 중인 명령을 끊는 원래 기능을 잃는데, 선택 유무로 가르면 둘 다 자연스럽다.

## 도중에 잡은 버그: 드래그 앵커가 밀림

`drag_started()`가 true가 되는 시점엔 egui의 드래그 판정 문턱만큼 포인터가 이미
움직인 뒤다. 그 위치를 선택 시작점으로 쓰면 **앞쪽 글자들이 선택에서 빠진다** —
테스트에서 "SELECTME"를 끌었는데 "ECTME"만 선택되는 것으로 드러났다.
`i.pointer.press_origin()`(실제로 버튼을 누른 좌표)을 앵커로 쓰도록 고쳤다.
테스트가 없었으면 "가끔 앞글자가 빠지네" 정도로 넘어갔을 종류의 버그다.

## 함께 발견한 별건: BUG-001

Ctrl+C 라우팅을 검증하다가 **실행 중인 명령이 Ctrl+C로 안 끊긴다**는 걸 발견했다.
내 변경 때문이 아니라 원래 그랬다(0x03 경로는 그대로 두고 앞에 가드만 추가했다).

`examples/ctrlc_check.rs`로 UI를 걷어낸 PTY 레벨에서 두 경우를 분리 재현:

| 상황 | 0x03 전송 결과 |
|---|---|
| 프롬프트에서 입력 중 | **동작** (`^C` 표시, 줄 취소) |
| 명령 실행 중 | **안 됨** (루프 계속) |

0x03은 셸에 도달한다. 문제는 명령 실행 중엔 PowerShell이 stdin을 읽지 않아서,
그때의 인터럽트는 콘솔 CTRL_C_EVENT로 와야 한다는 것 — ConPTY가 자동 승격을
안 해준다. 별도 퀘스트 [[BUG-001]]로 분리했다.

그래서 이 퀘스트의 테스트는 "실행 중인 명령이 끊기는지"를 단언하지 않는다.
대신 **프롬프트에서 치던 줄이 취소되는지**로 0x03이 실제 전달됐음을 확인한다
(이건 정상 동작하는 경로다).

## 검증
- `drag_selection_then_ctrl_c_copies_selected_text` — 실제 PowerShell 출력 위에서
  합성 마우스 이벤트로 드래그 → 정확히 "SELECTME"만 선택되고 클립보드로 나감
  (`platform_output.commands`의 `CopyText`로 확인)
- `ctrl_c_without_selection_sends_interrupt_instead_of_copying` — 복사가 아니라
  0x03로 가고, 셸이 `^C`를 찍고 줄을 버리며, 취소한 명령이 실행되지 않음
- `typing_clears_selection`
- `pos_to_cell_accounts_for_scrollback_offset` — 스크롤백 10줄 올린 상태에서 같은
  화면 위치가 그리드 좌표로 10줄 위를 가리키는지(렌더 루프가 반대로 더하는 것과 짝)
- `cargo test --workspace`: 42개 전부 통과(core 25 + ui 17)

## 남은 것 (이 퀘스트의 나머지)
- **IME 조합 입력** — 이 퀘스트의 진짜 난점. winit IME preedit/commit 이벤트,
  조합 중 글자를 커서 위치에 렌더링, 후보창 위치 지정. 성격이 완전히 달라 2차 패스로 분리.
- 블록 선택(Alt+드래그) — `SelectionType::Block`이 이미 있어서 붙이기는 쉽다
- 마우스 리포팅(vim 등 TUI 앱이 마우스를 직접 받는 모드) — 이게 없으면 TUI 앱
  안에서 드래그하면 앱 대신 우리 선택이 동작한다
- bracketed paste mode
- 선택 후 우클릭/중클릭 복사·붙여넣기 같은 마우스 관례
