## 구현 완료 — 자동 검증 결과 (관통 지점)

`syncshell-core::sync::SyncState`로 단일 진리원을 두고, `syncshell-ui`의 `App::ui()`에서
양방향으로 연결했다. 탐색기 → 터미널은 `sync.user_navigated()`(실제 클릭 시에만 호출),
터미널 → 탐색기는 매 프레임 `session.cwd`를 `sync.terminal_cwd_changed()`에 흘려보내는
방식. 두 함수를 분리해서, "사용자가 진짜 클릭했다"와 "동기화로 화면만 옮긴다"가
호출부 레벨에서 섞이지 않게 했다 — 동기화로 옮긴 경우는 `FsView::navigate`를 직접
불러서 `sync`를 다시 거치지 않는다.

### 구현 중 발견하고 고친 버그 — 에코 억제 설계

최초 설계는 "주입한 cd로 다음에 기대하는 경로"를 별도 슬롯(`expecting_from_injection`)에
저장해두는 방식이었다. 코드를 실행하기 전에 손으로 시나리오를 추적하다가, **폴더를
연달아 두 번 클릭(A→B)하면 중간값 A의 지연된 에코가 도착했을 때 최종값 B의 진짜
확인 이벤트가 "이미 기대 중이던 값"으로 오인되어 억제당하고, 탐색기가 A에 멈춘 채
다시는 B로 안 움직이는 버그**를 발견했다. 별도 슬롯을 없애고 `current`(탐색기가 지금
보여주는 경로) 하나와의 단순 비교로 바꿔서 해결 — 이 설계는 무한루프 걱정이 원래
없다(터미널→탐색기 방향은 절대 터미널에 다시 주입하지 않으므로), 그래서 echo 판정을
"완벽히" 할 필요가 없고 그냥 "최신 상태로 항상 수렴"하기만 하면 충분하다는 걸 깨달았다.
`sync.rs`에 회귀 테스트로 남겨뒀다(`rapid_double_click_always_converges_to_final_state`).

### 자동 테스트
- `cargo test -p syncshell-core`: 11개 유닛 테스트 전부 통과 (osc7 4개, fsview 2개, sync 5개)
- `cargo run -p syncshell-core --example sync_check`: **실제 TerminalSession + SyncState**로
  PowerShell을 띄워 헤드리스 End-to-End 검증. 5개 시나리오 전부 PASS:
  1. 초기 동기화(터미널의 %USERPROFILE% 기본값으로 탐색기가 맞춰짐 — TR-004에서 지적한
     초기 불일치가 첫 OSC7 감지로 자연히 해소되는 것 확인)
  2. 탐색기 클릭 → 터미널 cd 반영 + 에코가 탐색기를 다시 안 옮김(최종 수렴 기준)
  3. 터미널에서 직접 cd → 탐색기 이동 이벤트 발생
  4. 한글+공백 경로 양방향 왕복
  5. **응답 대기 없는 연속 클릭(A→B) → 최종적으로 B에 정확히 안착** (위에서 고친 버그의
     실제 PTY 재현 테스트)

### 예상 밖의 발견 — PSReadLine 프롬프트 재렌더링 아티팩트

`sync_check` 2번/4번 시나리오에서, 클릭 직후 `explorer_moves`에 **옛 경로가 한 번
더 찍히는** 현상을 관찰했다(예: `["C:\Users\User", "C:\Windows"]` — 기대는
`["C:\Windows"]` 하나뿐). 원인으로 보이는 것: PowerShell 5.1 + PSReadLine이 새 입력을
처리하기 직전에 **이전 상태의 프롬프트를 한 번 더 redraw**하는 것으로 보임 (OSC7이
중복으로 한 번 더 찍힘). 최종 상태로는 항상 정확히 수렴하므로(5번 테스트가 이를
증명) 기능적으로 깨지지는 않지만, **실제 UI에서는 탐색기가 클릭 직후 한 프레임
정도 옛 폴더로 깜빡였다가 새 폴더로 안착하는 것처럼 보일 수 있다.** 이건 화면을
직접 봐야 판단 가능한 부분이라 TR-006(사람 검증)에서 확인 필요. 거슬리면 후속
작업으로 OSC7 이벤트를 짧게(예: 50ms) 디바운스/코얼레싱하는 걸 고려할 것 — DEV-006
(양방향 동기화 완성) 범위로 넘긴다.

### 감수한 한계 (기존 계획대로)
- 동기화 on/off 토글 없음
- 명령 입력 중 주입 시 입력 버퍼 보존 없음
- 경로 인용은 최소한만(`cd "path"` 더블쿼트) — 따옴표 포함 경로 등은 미대응
- 탭/분할별 독립 동기화 없음(1개뿐이므로 해당 없음)

### 화면 확인이 필요한 부분 (TR-006에서)
- 탐색기 클릭 → 터미널 프롬프트가 실제로 그 경로로 바뀌는 게 눈으로 보이는지
- 위에서 발견한 PSReadLine 재렌더링으로 인한 깜빡임이 거슬리는 수준인지
- 터미널에서 `cd` 입력 → 왼쪽 목록이 따라 올라가는 게 자연스러운지
