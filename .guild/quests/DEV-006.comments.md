## 상태 확인 + 빠진 기능(동기화 토글) 구현

기존 SyncState 로직(연속 클릭 수렴, cd .. 추적, 입력 중 보존)은 이미 `sync.rs`
유닛테스트로 촘촘히 커버돼 있었고 플랫폼 비의존 순수 로직이라 macOS에서도 그대로
통과함(cargo test --workspace, 25/25). 그런데 Test plan 마지막 항목 —
**"동기화 일시 해제 토글"** — 은 코드베이스 전체를 grep해도 어디에도 없어서
실제로 미구현이었다. 이번에 구현함:

- `FilePanelState.sync_enabled: bool`(기본값 `true`) 추가, 패널 헤더에
  "터미널과 동기화" 체크박스 추가(`file_panel.rs`).
- 껐을 때: 탐색기 클릭 → `cd` 주입 안 함(`lib.rs::handle_file_action`), 터미널
  cwd 변화 → 탐색기 자동 이동 안 함(`lib.rs::ui()`). 단 `SyncState.current`
  자체는 토글과 무관하게 계속 최신으로 갱신해둔다 — 토글을 다시 켰을 때 기준이
  낡아있지 않게 하기 위함.
- 우클릭 메뉴의 "여기서 터미널 열기"(`OpenTerminalHere`)는 토글과 무관하게 항상
  동작하도록 그대로 둠 — 그건 자동 추종이 아니라 사용자의 명시적 1회성 명령이라서.
- 테스트 2개 추가(`file_panel.rs`): 기본값이 켜짐인지, 실제 체크박스를
  합성 클릭했을 때 꺼지는지(진짜 프로덕션 `show()` 코드로 확인).

**알려진 한계**: 토글을 껐다가 다시 켰을 때, 그 사이 양쪽이 따로 움직였다면
재활성화 직후 첫 이벤트 1회는 부정확하게 동기화될 수 있다(예: 낡은 기준으로
상대경로 cd 계산). "재연결 시 정합" 같은 별도 로직은 없음 — 스펙이 요구하는
범위를 넘어서는 것 같아 지금은 구현하지 않음.

## 실사용 버그 수정: cd 주입 타이밍/명령 실행 중 보호

**리포트 1**: "터미널에 명령어를 입력해둔 채로 탐색기에서 위치를 바꾸고
엔터를 치면(입력해뒀던 명령을 실행하면) 이전 위치에서 명령이 실행됨".

원인: 사용자가 아직 제출 안 한 줄을 타이핑 중일 때 cd 주입을 `pending_cd`에
미뤄뒀다가, Enter를 누르는 그 순간(`pending_user_input`이 false가 됨) 다음
프레임에 흘려보내고 있었다 — 그런데 Enter 자체는 이미 그 프레임에 셸로
전달되어 옛 위치에서 실행이 시작된 뒤였다. "미루기"의 순서가 잘못됐던 것.

고침: 타이핑 중에 탐색기가 이동하면 그 줄을 0x03(BUG-001에서 모든 셸에서
프롬프트 줄을 취소하는 걸로 이미 검증된 방법)으로 취소하고 cd를 곧바로
적용한다. 타이핑하던 내용은 사라지지만(다시 쳐야 함), "엉뚱한 위치에서
실행됨"보다는 안전한 트레이드오프라고 판단. 새 텍스트를 줄 앞에 안전하게
끼워 넣는 방법은 없다(Home/Ctrl+A 같은 커서 이동 키가 셸·키바인딩마다 달라
신뢰 못함 — 검토했지만 채택 안 함).

**질문 답변**: "터미널에서 명령이 실행되는 도중에 탐색기에서 위치를
바꾸는 경우에 대한 방어 처리는?"

**있었던 방어가 실은 구멍이 있었다.** `pending_user_input`은 Enter를 누르는
순간 곧바로 false가 되는데, 이건 "제출 안 한 줄이 있는가"만 추적하지 "셸이
지금 명령을 실행 중인가"는 추적하지 않았다. 그래서 명령 실행 중에 탐색기가
이동하면 cd 바이트가 **곧바로** PTY에 써졌다 — 커널 tty 입력 큐에 쌓였다가
지금 실행 중인 프로그램이 stdin을 읽는 종류(REPL·페이저·대화형 프롬프트
등)라면 엉뚱하게 그리로 들어갈 수 있는 상태였다.

`TerminalSession`에 `command_running` 플래그를 새로 추가해서 고침: Enter로
(빈 줄이 아닌) 명령을 제출한 순간 true, 다음 OSC7 프롬프트가 뜨면 false —
`inject_cd`가 이제 이것도 확인해서, 명령 실행 중이면 (원래 있던) `pending_cd`
지연 메커니즘으로 미룬다. 실제 zsh로 `sleep 2` 실행 중 상태를 검증
(`examples/zsh_command_running_check.rs`, `examples/zsh_cd_while_typing_check.rs`)
— 둘 다 PASS.

## 후속 개선: 타이핑하던 내용을 지우지 않고 새 폴더로 이어가기

이전 코멘트에서 "타이핑 중 위치 변경 시 그 줄을 취소(0x03)하고 cd 적용"으로
고쳤는데, 사용자 요청으로 한 단계 더 개선함 — 취소해서 잃어버리는 대신
**타이핑하던 내용을 그대로 유지한 채 새 폴더로 넘긴다.**

`\x1b[H`(ANSI Home 시퀀스)로 먼저 시도했으나 zsh 줄 편집기가 이걸 "줄 맨
앞으로 이동"으로 해석하지 않아(라인 끝에 그대로 이어붙여짐) 실측으로
기각. `\x01`(Ctrl+A — bash/zsh 기본 이맥스 키바인딩)로 실측해보니 정확히
줄 맨 앞으로 이동함을 확인. `TerminalSession`에
`supports_line_prefix_insert` 필드를 추가(지금은 zsh만 true — 셸 종류는
스폰 시점에 이미 판별하고 있어서 그 정보를 재사용)해서, `inject_cd`가
타이핑 중 위치 변경을 감지하면:

- **zsh 등 지원 셸**: Ctrl+A로 커서를 줄 맨 앞으로, "cd 새경로; "를 끼워
  넣는다(제출은 안 함 — 사용자가 Enter를 누르면 "cd 새경로; 원래타이핑"
  형태로 새 위치에서 그대로 실행됨).
- **PowerShell 등 미지원 셸**: 기존 방식(0x03으로 줄 취소 후 cd 즉시 적용)
  으로 폴백. PSReadLine 기본("Windows") 모드는 Ctrl+A가 "줄 맨 앞으로"가
  아니라 "전체 선택"이라, 그 상태에서 새로 타이핑하면 선택된(=사용자가
  치던 전체 줄) 내용을 지워버려서 오히려 더 위험함 — Windows에서 검증할
  방법이 없어 안전한 쪽으로 유지.

실제 zsh로 검증(`examples/zsh_cd_while_typing_check.rs` 갱신): "echo hello"를
타이핑한 채 폴더 이동 → 삽입 → Enter → 새 폴더에서 "echo hello"가 정상
실행되고 pwd도 새 위치를 가리킴. PASS.

## 질문 답변: "명령 실행 중 방어 처리하면 동기화가 깨지는 거 아님?"

**엄밀히 말하면 일시적으로는 그렇다 — 다만 SyncState 로직 자체가 깨지진
않는다.** 명령 실행 중에 탐색기를 클릭하면:

- 탐색기 뷰는 **즉시** 새 폴더로 바뀐다(`fs.navigate`가 곧바로 호출됨).
- `SyncState.current`도 **낙관적으로 즉시** 새 경로로 갱신된다
  (`sync.user_navigated`가 cd 주입 여부와 무관하게 먼저 불림).
- 하지만 터미널(셸 프로세스)의 실제 cwd는 **명령이 끝날 때까지** 옛 위치
  그대로다 — `pending_cd`에 담아뒀다가 명령이 끝나고 새 프롬프트가 뜨면
  그제서야 실제로 `cd`가 셸에 전달된다.

그래서 "명령이 실행되는 동안"은 탐색기가 보여주는 위치와 터미널이 실제로
있는 위치가 다른 상태가 맞다(탐색기가 "곧 도착할 곳"을 미리 보여주는
셈). 하지만 이게 버그로 이어지진 않는다 — 나중에 실제 cd가 실행되면서
셸이 OSC7으로 그 위치를 보고할 때, `SyncState.current`가 이미 그 경로로
낙관적 갱신돼 있어서 "에코"로 인식돼 탐색기를 다시 옮기려 하지 않는다
(중복 네비게이션도, 되돌아감도 없음) — 최종적으로는 항상 정확히 수렴한다.

다만 **명령이 실행되는 동안 두 패널이 서로 다른 위치를 보여준다는 사실
자체**는 시각적으로 남는다. 지금은 이걸 구분해서 보여주는 UI가 없다 —
필요하면 "터미널이 아직 여기로 안 옴, 명령 끝나면 이동 예정" 같은 표시를
추가할 수 있는데, 이건 범위를 넘어서는 것 같아 우선 언급만 해둠.

## 정정: 동기화 토글 제거함 (위 코멘트들에서 만든 기능)

위 코멘트에서 구현했던 "터미널과 동기화" 토글은 이후 사용자 피드백으로
**완전히 제거**했다 — 버그(껐다 켜도 재동기화 안 됨)도 있었고, 애초에
사용자가 기대하지 않았던 기능("난 항상 동기화되는걸 생각했었는데")이었다.
자세한 사유와 대안(다중 탭으로 대체)은 [[DEV-019]] 참고 — 그 퀘스트를
새로 만들어서 곧바로 Cancelled로 남겨뒀다.

지금은 다시 원래대로(항상 양방향 자동 동기화, 토글 없음) 동작한다. 위
코멘트들의 "sync_enabled"/"토글" 관련 서술은 더 이상 코드 상태와 안 맞으니
참고할 때 주의할 것 — 나머지(에코 억제, 낙관적 갱신, cd 주입 타이밍 등)는
여전히 유효함.
