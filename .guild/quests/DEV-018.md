## 배경

프로젝트는 처음부터 Windows(ConPTY/PowerShell) 대상으로 개발되어 왔고,
architecture 규칙 1번이 "2단계(WSL)·3단계(Linux/macOS) 이식"을 core/UI
분리로 미리 대비해뒀다. 이번 퀘스트는 그 3단계 중 macOS 실행을 실제로 뚫었다.

## 발견/수정한 문제

1. **빌드 자체가 안 됨**: `alacritty_terminal` 0.24.2가 유닉스 타깃에서 쓰는
   `rustix-openpty`가 `rustix 0.38`을 `default-features = false`로 당겨와서
   `std` 피처가 빠지고, `rustix::fd::OwnedFd`가 `std::os::fd::OwnedFd`와 다른
   타입이 되어 컴파일이 깨짐. `syncshell-core`에 `rustix`를 `std` 피처 포함으로
   직접 선언해 feature unification으로 우회(`crates/syncshell-core/Cargo.toml`
   `[target.'cfg(unix)'.dependencies]`).

2. **셸이 `powershell.exe`로 하드코딩**: `syncshell-ui/src/lib.rs`가 항상
   `"powershell.exe"`를 스폰해서 macOS에서 터미널이 아예 안 뜸. `default_shell()`
   (`syncshell-core/src/terminal.rs`)을 추가해 Windows는 PowerShell,
   그 외에는 `$SHELL`(없으면 `/bin/zsh`)을 쓰도록 함.

3. **zsh용 OSC7 cwd 동기화가 없었음**: architecture 규칙 4번(cwd 추적은 OSC7이
   주 방식)을 zsh까지 확장. PTY 기동 직후 "타이핑하듯" 주입하는
   `zsh_injection_script()`를 추가 — `precmd` 훅(`add-zsh-hook`)에서 매
   프롬프트 렌더링 직전 OSC7을 찍는다. **`unsetopt MULTIBYTE`가 핵심**: 안
   그러면 zsh의 문자 인덱싱이 코드포인트 단위로 돌아 한글 등 비ASCII 경로의
   percent-encoding이 디코더가 기대하는 UTF-8 바이트 단위와 어긋난다.
   `crates/syncshell-core/examples/zsh_osc7_check.rs`(osc7_check.rs의 zsh
   대응, 헤드리스 확인용)로 한글+공백+`%`/`#` 특수문자 경로, 루트("/"), 연속
   cd까지 실제 zsh로 검증 — 전부 PASS.

4. **OSC7 디코더가 Windows 경로만 만듦**: `osc7.rs`의 `decode_payload`가
   무조건 `\`로 조립하고 드라이브 문자를 처리했음. `cfg(windows)`/`cfg(not(windows))`로
   분리해 유닉스에서는 `/`를 유지하고 앞에 `/`만 복원하도록 함.

5. **macOS FSEvents 워처가 아무 것도 못 잡음**: `fsview.rs`가 이벤트 경로를
   `self.current_dir`와 문자열로 직접 비교했는데, macOS FSEvents는 심볼릭
   링크를 실제 경로로 정규화해서 돌려준다(`/var/...`로 감시해도 이벤트는
   `/private/var/...`로 옴 — `/var`가 `/private/var`의 심볼릭 링크라서).
   `matches_current_dir()`(정규화 폴백 비교)를 추가하고, `apply_change`에
   넘기는 경로도 `current_dir.join(name)`으로 재조립해 기존 entries의 경로
   문자열과 일치시킴. 실제 notify 이벤트 스트림을 헤드리스 프로브로 직접
   찍어보고서야 원인을 확정함(디렉터리 레벨 spurious 이벤트 + 파일 레벨 진짜
   이벤트가 별도 배치로 옴을 확인).

6. **크로스플랫폼 테스트 버그**: `sync.rs`/`file_panel.rs`의 유닛 테스트가
   `PathBuf::from(r"C:\...")` 백슬래시 리터럴을 썼는데, 유닉스에서는 `\`가
   구분자가 아니라서 `parent()`/`file_name()` 계산이 실제로 깨짐(문자열
   비교 자체는 통과해도 로직 검증이 무의미해짐). 슬래시 경로로 교체.
   `fsview.rs`의 심볼릭 링크 테스트는 `std::os::windows::fs::symlink_dir`를
   무조건 호출해 유닉스에서 컴파일 자체가 안 됐음 — `cfg`로 분기.

7. **`terminal_widget.rs`의 PTY 통합 테스트 12개**: 실제 PowerShell 프로세스와
   그 출력 포맷(`Write-Host`, `PSReadLine` 등)에 의존해 macOS로 옮길 수 없는
   테스트라 `#[cfg(windows)]`로 게이팅(로직 자체는 안 건드림 — Windows CI에서는
   그대로 전부 돈다). `SelectionHarness`도 같이 게이팅.

## 검증

- `cargo build --workspace` / `cargo test --workspace` 전부 통과(macOS, Apple Silicon).
- `cargo run -p syncshell-core --example zsh_osc7_check` — 실제 zsh로 cwd 동기화 왕복 확인, 전부 PASS.
- `./target/debug/syncshell`을 직접 실행해 크래시 없이 뜨고 정상 종료되는 것 확인.

## Test plan (사람 확인 필요)

- [ ] 앱을 실제로 띄워서 창이 뜨고 터미널에 zsh 프롬프트가 나오는지 육안 확인
- [ ] 탐색기에서 폴더 클릭 → 터미널에 `cd` 주입되는지, 반대로 터미널에서
      `cd`했을 때 탐색기가 따라가는지(양방향 동기화) 실제로 눌러서 확인
- [ ] 한글 경로가 포함된 폴더로 왕복 이동해도 깨지지 않는지 확인
- [ ] Ctrl+C가 실행 중인 명령/줄 취소 양쪽에서 잘 동작하는지 확인(유닉스
      PTY는 커널 tty 드라이버가 0x03을 SIGINT로 승격해주므로 Windows처럼
      별도 콘솔 API가 필요 없을 것으로 예상되지만 실측은 아직 안 함)
- [ ] 폰트/한글 렌더링이 macOS 시스템 폰트에서도 깨지지 않는지 확인
