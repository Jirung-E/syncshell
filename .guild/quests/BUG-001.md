**실행 중인 명령을 Ctrl+C로 끊을 수 없다.** 터미널의 기본 기능이 빠져 있어서,
잘못 실행한 명령이나 오래 걸리는 명령을 중단할 방법이 없다(앱을 닫는 것 말고는).

## 증상

프롬프트에서 치던 줄을 취소하는 건 **정상 동작**한다 — PSReadLine이 `^C`를 찍고
줄을 버린 뒤 새 프롬프트를 낸다.

반면 **명령이 실행 중일 때**는 Ctrl+C가 아무 효과가 없다. 예를 들어
`while ($true) { Start-Sleep -Milliseconds 50 }` 를 돌려놓고 Ctrl+C를 눌러도
루프가 계속 돌고, 이후 입력한 명령은 큐에만 쌓인 채 실행되지 않는다.

## 원인

`examples/ctrlc_check.rs`로 UI를 전부 걷어낸 PTY 레벨에서 두 경우를 분리해
재현했다. 결과:

| 상황 | 0x03 전송 결과 |
|---|---|
| 프롬프트에서 입력 중 | **동작** (`^C` 표시, 줄 취소) |
| 명령 실행 중 | **안 됨** (루프 계속) |

즉 0x03(ETX)은 셸에 **도달하고 있다**. 문제는 명령 실행 중에는 PowerShell이
stdin을 읽지 않는다는 것 — 그때의 인터럽트는 stdin 바이트가 아니라 콘솔의
**CTRL_C_EVENT**로 전달돼야 하고, ConPTY는 입력 바이트를 그 이벤트로 자동
승격해주지 않는다.

## 해결 방향 (착수 시 검증할 것)

- Windows: 자식 프로세스 그룹에 `GenerateConsoleCtrlEvent(CTRL_C_EVENT, pid)`.
  호출하려면 그 콘솔에 붙어 있어야 해서(`AttachConsole`), 우리 프로세스의
  콘솔 상태를 건드리지 않고 되는지 확인이 필요하다. 별도의 작은 헬퍼 프로세스를
  띄우는 방식도 후보.
- `portable-pty`가 이미 제공하는 게 있는지 먼저 확인할 것 (`Child::kill`은
  종료지 인터럽트가 아니라 그대로 쓸 수 없다).
- Unix(2·3단계): `killpg(pgid, SIGINT)`. 여기선 훨씬 단순하다.
- 플랫폼 분기는 `syncshell-core/src/pty.rs`에 가둔다 — 위젯은 "인터럽트 보내라"만
  알아야 한다(architecture 규칙: core는 UI를 모르고, UI는 플랫폼을 모른다).

## 주의

Ctrl+C의 **라우팅**(선택이 있으면 복사, 없으면 인터럽트)은 DEV-012에서 이미
구현했고 테스트도 있다. 이 퀘스트는 그중 "인터럽트" 쪽이 실제로 셸에 먹히게
만드는 것이다 — 라우팅 로직은 건드릴 필요 없다.

## Test plan
- 무한 루프 실행 중 Ctrl+C → 루프가 끊기고 프롬프트 복귀
- 오래 걸리는 실제 명령(`Get-ChildItem C:\ -Recurse`) 중 Ctrl+C → 중단
- 프롬프트에서 입력 중 Ctrl+C → 기존처럼 줄만 취소(회귀 없음)
- Ctrl+C로 셸 자체가 죽지 않는지
- 선택이 있을 때의 Ctrl+C는 여전히 복사(DEV-012 동작 회귀 없음)
