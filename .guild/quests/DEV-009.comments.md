**주의: 지금 이 퀘스트의 탭 설계와 사용자가 말한 탭이 같은 것인지 확인 필요.**
현재 범위는 "탭 하나 = (탐색기 경로 + 터미널 세션) 쌍"으로, 앱 전체의
작업 단위를 탭으로 나누는 모델이다. 사용자가 참조한 "Windows 기본 파일
탐색기의 탭"(Windows 11부터 추가된 기능)은 **탐색기 패널 자체의 다중
탭**(터미널과 무관하게 탐색기만 여러 폴더를 탭으로 열어두는 것)에 더
가까울 수 있다.

2. 탐색기 패널만 별도로 다중 탭을 갖게 할지(터미널과는 별개로)
3. 둘 다 필요한지(예: 앱 탭 안에 탐색기 서브탭)

## 착수 시 확인할 것: Ctrl+C 인터럽트와의 충돌 (BUG-001)

탭이 생기면 한 프로세스 안에 PTY 세션이 여러 개가 된다. 그런데 BUG-001에서 구현한
Ctrl+C 인터럽트는 **대상 셸의 콘솔에 잠깐 붙었다 떼는** 방식이고, 콘솔 붙임/뗌은
프로세스 전역 상태다.

그래서 **한 탭에서 Ctrl+C를 누르는 동안 다른 탭의 셸이 영향을 받을 수 있다.**
테스트 스위트에서 실측으로 확인된 현상이다 — 인터럽트를 태우는 테스트를 병렬로
돌리면 무관한 PTY 테스트 3~4개가 매번 다르게 실패했다.

별도 헬퍼 프로세스로 격리하는 방법을 시도했지만 **헬퍼에서는 이벤트가 전달되지
않는다**(BUG-001 댓글에 실험 결과 정리됨). 탭 작업 시 다시 검토할 것.

## 다중 탭 구현 — 분할 터미널은 아직

### 구현한 것
`SyncShellApp`을 단일 세션 구조에서 `tabs: Vec<Tab>` + `active: usize`로
리팩터링. `Tab`이 기존에 앱이 직접 갖고 있던 걸 그대로 옮겨 담는다(탐색기·
터미널 세션·동기화 상태·대기 중인 cd·패널 상태 전부 탭마다 독립).

- 탭 추가/닫기/전환, 단축키(Ctrl/Cmd+T 새 탭, Ctrl/Cmd+W 닫기, Ctrl/Cmd+Tab
  다음 탭, +Shift 이전 탭 — 단축키는 `consume_key`로 입력 큐에서 제거해서
  터미널에 새는 것 방지)
- 새 탭은 지금 보던 탭의 폴더에서 시작(매번 실행 위치로 되돌아가지 않음)
- 마지막 탭은 못 닫음(창을 닫으면 됨) — 탭 0개 상태 방지
- 탭의 셸이 종료되면(예: `exit`) 그 탭만 닫히고(탭이 여러 개일 때), 마지막
  탭이면 창까지 닫힘
- 탭 인덱스 계산(추가/앞탭 닫기/활성탭 자체 닫기/마지막탭 보호) 유닛테스트로
  검증 — 오프바이원이 나기 쉬운 영역이라 직접 확인함

### 알려진 한계(코드 주석에도 남김)
탭마다 `TerminalWidget`(→`FontFallback`)이 독립이라, 코드포인트 폴백을
동적으로 추가할 때(`ensure_covers`)마다 egui의 전역 폰트 테이블을 자기가
아는 것만으로 통째로 덮어쓴다. 그래서 한 탭이 방금 찾은 폴백 폰트를, 다른
탭이 (그건 모르는 채) 자기 폴백을 등록하며 되돌려버릴 수 있다 — 드문
비ASCII 글자가 탭 전환 후 일시적으로 두부로 보였다가, 그 탭이 그 글자를
다시 그리는 프레임에 스스로 복구되는 정도의 시각적 결함(데이터 손상·크래시
아님). 제대로 고치려면 `TerminalWidget::show()`의 공개 시그니처를 바꿔
`FontFallback`을 앱 전역에서 하나만 공유해야 하는데, 그 API를 쓰는 Windows
전용 테스트가 열 곳 넘게 있고 이 머신(macOS)에서는 `#[cfg(windows)]`라
컴파일조차 안 돼서 검증할 방법이 없다 — 확인 안 된 변경으로 Windows 빌드를
깨뜨릴 위험을 피하려고 지금은 손대지 않음.

### 안 한 것 — 분할 터미널
"터미널 분할(수평/수직), 분할된 각 패널이 자체 PTY 보유, 활성 패널 포커스에
따라 탐색기 동기화" 부분은 아직 손 안 댔다. 탭 하나만으로도 이번에 구조를
크게 바꾼 참이라, 분할까지 같이 하면 검증 없이 한 번에 너무 많은 게 바뀐다고
판단해서 나눴다. 참고로 "결정할 것"으로 남아있던 설계 질문(분할 패널이
여러 개일 때 탐색기가 활성 패널만 따라갈지, 같이 분할될지)은 분할을 실제로
구현할 때 VS Code 방식(탐색기 하나, 활성 패널만 따라감)을 기본값으로 제안함
— 탐색기까지 분할하는 건 지금 단일 탐색기 패널 가정이 코드 전반(sync.rs,
file_panel.rs)에 퍼져 있어 비용이 훨씬 큼.
