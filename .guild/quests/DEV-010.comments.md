## 구현한 것

`syncshell-core`에 `session` 모듈 추가:

- `syncshell_home()` — `SYNCSHELL_HOME` 오버라이드 우선, 아니면 `~/.syncshell`
  (Windows는 `%USERPROFILE%`). 호출부가 경로를 직접 조립하지 않도록 이 함수
  하나로 격리(메모에서 명시한 요구사항).
- `config.toml`(사람이 씀): `default_shell`, `sync_enabled_default`. 지금 앱에
  실제로 있는 설정 가능한 값만 넣었다 — 테마/키바인딩처럼 아직 기능 자체가
  없는 걸 미리 만들지 않음.
- `state.toml`(앱이 씀): 탭 목록(경로), 활성 탭 인덱스, 창 위치/크기.
- 원자적 쓰기(임시 파일 → rename), 손상 시 `.bak`로 백업 후 기본값 복구,
  Windows에서 `SetFileAttributesW`로 폴더 숨김 처리(탐색기 앱이 자기가 만든
  폴더를 자기 화면에 노출하는 것 방지).
- `resolve_existing_or_fallback`: 세션 복원 시 저장된 경로가 사라졌으면 존재
  하는 조상 폴더까지 조용히 올라가고, 그마저 없으면 기본 시작 위치로 폴백.

`syncshell-ui` 쪽 배선(`lib.rs`):
- `run()`이 시작 전에 `state.toml`을 읽어 창 크기/위치를 복원(eframe이
  `NativeOptions`로 창을 먼저 만들고 나서 `App::new`를 부르는 구조라, 여기서
  미리 읽어야 함).
- `SyncShellApp::new`이 저장된 탭들을 복원(경로별로 `resolve_existing_or_fallback`
  적용), `config.toml`의 `default_shell`/`sync_enabled_default`를 모든 탭
  생성에 반영.
- `eframe::App::on_exit()`(persistence cargo feature와 무관하게 항상 불리는
  훅)에서 현재 탭들의 경로·활성 인덱스·창 크기를 `state.toml`에 저장.
  `config.toml`은 절대 여기서 안 건드림(사람이 쓴 파일).
- 창 위치/크기는 `on_exit`에 `Context`가 안 넘어와서, 매 프레임 `ui()`에서
  `last_window_rect`에 캐시해뒀다가 종료 시 그 마지막 값을 쓴다.

## 검증

- 유닛테스트 11개(`session.rs` 10개 + `lib.rs` 1개): 왕복 저장/복원, 주석
  보존(설정 파일에 절대 안 씀), 손상 파일 복구+백업, 원자적 쓰기(임시 파일
  안 남음), 조상 폴더 폴백, `on_exit`이 실제로 탭/활성탭/창크기를 저장하는지.
- 실제로 `SYNCSHELL_HOME`을 격리된 임시 디렉터리로 지정해 앱을 띄워보고:
  - `~/Library/Application Support/syncshell` 등 흔한 누수 위치에 아무것도
    안 생기는지 확인 — 안 생김
  - 실제 사용자의 `~/.syncshell`을 건드리지 않는지 확인 — 안 건드림
- **한계**: 이 자동화 환경에서 진짜 OS 창 닫기 이벤트(빨간 버튼, Cmd+Q)를
  재현할 방법이 없었다(`kill -TERM`은 winit 이벤트 루프를 안 거쳐서
  `on_exit`이 안 불림 — 직접 실측해서 확인함). `on_exit()`의 저장 로직
  자체는 직접 호출하는 테스트로 검증했지만, **실제 창을 닫았을 때 그게
  진짜로 불리는지는 사람이 확인해야 한다.**
