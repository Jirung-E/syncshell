Windows에서 터미널에 키를 꾹 누르면 OS 반복 속도보다 느리게 입력되고, 키를 뗀 뒤에도 밀린 입력이 한동안 계속 들어간다. 그 사이 마우스 이동·창 크기 변경도 같이 버벅인다(앱 전체가 느림). 2026-10-04 Windows 사용자 확인, `cargo run --release`.

## 지금까지 확인한 것
- 같은 PowerShell을 Windows Terminal에서 쓰면 정상 → 셸(PSReadLine) 자체 문제 아님
- macOS에서 release 프레임 비용 실측: 터미널 그리기 0.2ms, 탐색기 0.04ms, 타이핑 중에도 1~2ms → 앱의 CPU 레이아웃 비용은 원인 아님(최소한 macOS에선)
- 코드 확인: 키 입력·PTY 출력은 프레임마다 쌓인 것을 전부 처리, `resize`는 크기 같으면 건너뜀, 프레임마다 도는 무거운 작업 없음
- 남은 후보(Windows 전용 경로): (a) 렌더러 present/vsync 대기, (b) UI 스레드의 PTY 쓰기(`write_all`)가 막힘, (c) OS 기본 ConPTY(System32) 성능 — WezTerm 등은 이 때문에 conpty.dll/OpenConsole.exe를 동봉

## 1단계: 진단 표시
`SYNCSHELL_PROFILE=1`로 실행하면 상태바에 프레임 간격·UI 처리 시간·PTY 쓰기 시간·PTY 출력량을 띄워 Windows에서 실제 수치로 원인을 가른다.

## 원인 (확정, 2026-10-11)
egui-winit 0.35이 IME 허용 중 입력 이벤트가 있는 프레임마다 `set_ime_cursor_area`를 불러, Windows에서 키마다 `ImmSetCompositionWindow`/`ImmSetCandidateWindow`가 끼어듦 → TSF 한국어 IME에서 키 반복이 ≈21회/초로 밀리고 뗀 뒤에도 계속 입력. IME를 끄면 30회/초·정상.

## 수정
- egui-winit 0.35.0을 `vendor/egui-winit`에 두고 그 조건을 "IME 영역이 바뀔 때만"으로 한 줄 패치(`[patch.crates-io]`)
- 진단 도구는 남겨 둠: `SYNCSHELL_PROFILE=1`, `SYNCSHELL_SELFTEST=keys|oskeys`, `SYNCSHELL_NO_IME=1`, `SYNCSHELL_NO_ACCESSKIT=1`, `input_latency_probe` 테스트

## Test plan (Windows, 사람 확인)
- 기본 실행(IME 켬)에서 영문 키를 3초 꾹 → OS 반복 속도로 들어가고 떼면 바로 멈추는지. `SYNCSHELL_PROFILE=1`이면 PTY 쓰기 ≈30회/초
- 한글 입력(DEV-012 회귀 확인): 한/영 전환 후 "안녕하세요" 조합·확정, 한글 키 꾹 눌러 반복
- 다른 창으로 갔다 돌아온 뒤에도 한글 조합이 커서 위치에 그려지고 한자 변환 후보창(있으면)이 엉뚱한 곳에 안 뜨는지
