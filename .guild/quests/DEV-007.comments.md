## 구현 완료

`notify-debouncer-mini`(내부적으로 `notify` — Windows에서는 ReadDirectoryChangesW)로
현재 표시 중인 디렉터리를 감시한다.

## 설계

- `FsView`에 `watcher: Option<Debouncer<RecommendedWatcher>>` 필드 추가.
  `new()`/`navigate()`에서 항상 새 워처로 교체한다 — 이전 값이 그 대입으로 drop되고,
  `Debouncer`의 `Drop` impl이 자동으로 이전 감시를 해제한다(퀘스트 스펙의
  "디렉터리 이동 시 감시 대상 교체 및 이전 워처 해제" 요구사항).
- `RecursiveMode::NonRecursive`로만 감시 — 지금 보이는 목록(바로 아래 항목들)의
  생성/삭제/이름변경/수정만 있으면 되고, 안 보이는 손자 이하 변경은 필요 없다.
- 디바운스 100ms(`WATCH_DEBOUNCE`) — 빌드 산출물 대량 생성처럼 이벤트가 몰릴 때
  한 번에 모아 처리한다(퀘스트 스펙 그대로).
- **전체 재조회 금지 스펙 반영**: `notify-debouncer-mini`는 이벤트 종류(생성/삭제/
  이름변경)를 구분해 주지 않고 "이 경로가 바뀌었다"만 알려준다(`DebouncedEventKind`가
  `Any`/`AnyContinuous`뿐). 그래서 폴더 전체를 다시 읽는 대신, 변경된 경로 하나만
  `stat`해서 있으면 목록에 추가/갱신하고 없으면 빼는 방식(`apply_change()`)으로
  처리했다 — 이름변경도 별도 케이스 없이 "옛 경로 삭제 이벤트 + 새 경로 생성
  이벤트" 두 개로 자연히 해결된다.

## 검증 (실제 파일시스템 + 실제 notify 워처)
- `watch_reflects_externally_created_file`: FsView 바깥에서 `std::fs::write`로
  파일을 만들면 폴더를 재조회하지 않고도 목록에 반영되는지 확인.
- `watch_reflects_externally_deleted_file`: 반대로 삭제가 반영되는지 확인.
- `navigate_switches_watch_to_new_directory`: 폴더 이동 후 새 폴더에 대한 감시가
  동작하는지(이전 워처가 자동 해제되고 새 워처로 정상 교체됐는지) 확인.
- `cargo test -p syncshell-core`: 19개 전부 통과(기존 sort/symlink 테스트 포함,
  회귀 없음).
- `cargo build --workspace`: 클린 빌드 확인.
