## 구현 현황 (예광탄 이후, TR-006 회고 반영)

**대부분 이미 구현됨.** `crates/syncshell-core/src/pty.rs` +
`src/terminal.rs`에 `portable-pty` 기반 `Pty` 인터페이스가 있고, 아래
범위 항목 전부 충족:
- spawn/write/resize 구현됨, 기본 셸은 Windows=PowerShell(하드코딩, 설정
  가능하게 만드는 건 아직 안 함)
- 입출력 채널 브리지 구현됨 (`PtyEvent::Data`/`Exited`)
- **셸 종료 감지**: 처음엔 read() EOF로 시도했으나 **ConPTY가 EOF를 신뢰성
  있게 안 준다는 걸 실측으로 확인**(`exit` 후 5초 대기해도 안 옴) —
  `Child::try_wait()` 폴링으로 교체함. `architecture` 길드 규칙 5번에 기록.
- 리소스 정리: `Pty`의 `Drop`에서 `child.kill()` — 좀비 프로세스 없음 확인.
- 리사이즈: **최소 크기 하한(20컬럼×4행) 강제 추가** — 극단적으로 좁게
  줄이면 alacritty_terminal이 스크롤백을 리플로우하다 ~5GB 메모리 할당
  크래시하는 걸 발견해서 막음. `architecture` 규칙 7번에 기록.

## 남은 것
- Unix(forkpty) 경로는 미검증 — 2·3단계 착수 전까지는 컴파일 확인도 안 함
  (cross-compile CI 항목 그대로 유효)
- 기본 셸을 설정으로 바꿀 수 있게 하는 것 (지금은 하드코딩)

## macOS/zsh에서 확인

- 새 헤드리스 확인 두 개 추가(osc7_check.rs/resize_loss_check.rs/exit_check.rs의
  zsh 대응, DEV-018 zsh_osc7_check.rs와 같은 패턴):
  - `examples/zsh_exit_check.rs`: `exit` 입력 → `TerminalSession.exited == true`,
    그리고 `ps -o state=`로 자식 프로세스가 좀비(Z)로 안 남고 완전히 정리되는지까지
    OS에 직접 물어봄. **PASS**.
  - `examples/zsh_resize_check.rs`: 넓은 출력 → `resize(1,1)`(MIN_COLS/MIN_ROWS
    clamp 경로) → 원래 크기로 복구 → 크래시/조기종료 없음, 완만한 리사이즈
    왕복(120→60→120) 후에도 실제 `ls` 출력이 정상 반영됨. **PASS**.
- 기본 셸 결정 로직(Windows=PowerShell, Unix=`$SHELL` 없으면 `/bin/zsh`)은
  DEV-018에서 이미 구현·검증(`terminal.rs::default_shell()`).
- "(3단계 대비) Unix 빌드에서 동일 코드가 컴파일되는지" — DEV-018에서 확인 완료
  (`cargo build --workspace`/`cargo test --workspace` 그린).

Windows 쪽 동작(PowerShell 대상 exit_check.rs/resize_loss_check.rs 등)은 안 건드림 —
그대로 유지.
