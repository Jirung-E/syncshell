UI 배율과 터미널 글자 크기를 **따로** 조절할 수 있게 한다(2026-10-11 사용자 요청: "ui조절과 터미널 글자크기 조절이 따로 되도록").

지금은 egui 기본 확대(Ctrl/Cmd + =/−/0)가 숨은 기능으로만 있고, 화면 전체(터미널 글자 포함)가 같이 커지며 저장도 안 된다. 터미널 글자는 16pt 고정.

## 범위
- 터미널 글자 크기: Ctrl/Cmd + = / − / 0, 터미널 위에서 Ctrl/Cmd + 휠 (일반 터미널 관례)
- UI 배율: Ctrl/Cmd + Shift + = / − / 0, Ctrl/Cmd + Shift + 휠(어디서든), 터미널 밖에서 Ctrl/Cmd + 휠 — 탭 바·탐색기·상태바 등 앱 전체 (2026-10-11 사용자 피드백 "마우스 휠로 앱 전체 크기는 왜 못 바꾸냐" 반영)
- 둘은 독립: UI 배율을 바꿔도 터미널 글자의 실제 화면 크기는 그대로(터미널 글자 pt = 글자 크기 / UI 배율)
- egui 기본 키보드 확대(`zoom_with_keyboard`)는 끈다 — 단축키 충돌
- 상태바 오른쪽에 "UI 100% · 글자 16" 표시, 누르면 각각 − / + / 초기화
- 두 값 모두 `state.toml` `[ui]`에 저장·복원
- 범위: UI 50~200%(10% 단위), 글자 8~40(1 단위), 기본 100% / 16

## 구현
- `scale.rs`: 배율·글자 크기 값/단계/범위, 단축키(물리 키 기준 — Shift 조합에서 `=`가 `+`로 들어오는 문제 회피), 상태바 메뉴
- 터미널 글자 pt = 글자 크기 / UI 배율 → UI 배율과 무관하게 화면 크기 유지
- 창 위치/크기 저장 시 egui 배율을 곱해 OS 단위로 되돌림 — 안 그러면 배율 120%로 끈 뒤 다시 켤 때 창이 줄어듦
- `state.toml [ui] ui_scale = 1.2, term_font_size = 19`

## Test plan
- 자동: 단계·범위·저장값 검증, 단축키 분리·소비(터미널로 안 샘), UI 배율과 무관한 터미널 화면 크기, 종료 상태 저장
- macOS 확인함: Cmd+= 3번 → 터미널 글자만 19, Cmd+Shift+= 2번 → UI만 120%(터미널 줄 간격 그대로), 종료 후 state.toml에 저장·창 크기 1280×760 유지
- 사람 확인(Windows): Ctrl+= / − / 0(글자), Ctrl+Shift+= / − / 0(UI), 터미널 위 Ctrl+휠(글자), 탐색기·탭 바 위 Ctrl+휠과 어디서든 Ctrl+Shift+휠(UI), 상태바 "UI 100% · 글자 16" 메뉴의 − / + / 기본값, 껐다 켜서 유지, 배율 바꾼 상태로 창 크기 유지
