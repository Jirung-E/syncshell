"콘솔창에서 위쪽 출력을 보기 위해 스크롤이 가능해야함" — 실사용 중 요청.

범위에 이미 있던 "스크롤백 스크롤, 휠/키보드 스크롤"이 예광탄에서는
의도적으로 생략됐던 항목인데(TR-002 "생략" 목록), 실사용에서 바로

구현 시 참고: `alacritty_terminal::Term`이 스크롤백 자체는 이미 들고 있음

`renderable_content()` 사용 부분은 이미 `display_offset`을 반영해서 그리고
있으므로 큰 구조 변경 없이 얹을 수 있을 것으로 보임(휠 이벤트 → offset 조정
+ repaint 정도).

## 스크롤백 스크롤 구현 (이 퀘스트 범위 중 일부)

사용자 피드백("콘솔창에서 위쪽 출력을 보기 위해 스크롤이 가능해야함")에 대응해
PageUp/PageDown/휠 스크롤을 구현했다.

## 실제로 찾은 버그 (진짜 원인)

`alacritty_terminal`의 `Term::renderable_content().display_iter`가 내놓는
`point.line`은 **grid 좌표계**(스크롤 안 된 활성 영역 기준 `Line(0)`)이지,
현재 뷰포트 기준 좌표가 아니다. `display_offset`(스크롤한 만큼)을 반영하려면
`point.line.0 + display_offset`으로 직접 변환해야 한다
(`alacritty_terminal::term::point_to_viewport()`와 같은 공식).

기존 렌더 루프는 `point.line.0`을 그대로 화면 y좌표로 썼고, 0 미만이면
그냥 건너뛰었다. `display_offset == 0`일 때는 우연히 맞아떨어지지만,
PageUp으로 `display_offset`이 커지는 순간 `display_iter`가 내놓는 모든
`point.line`이 음수가 돼 전부 걸러져서 **화면이 완전히 빈 채로 그려졌다**.
회귀 테스트(`pageup_reveals_older_scrollback_content`)로 처음엔 "스크롤이
전혀 안 되는 것처럼" 보였는데, 실제로는 `display_offset`은 정상적으로 바뀌고
있었고(진단 출력으로 확인) 렌더링 쪽에서 좌표 변환을 안 해서 안 보인 것뿐이었다.

커서 렌더링도 같은 문제가 있었다 — `cursor.point`는 항상 활성 영역 좌표라
스크롤백을 보고 있을 때는 뷰포트 밖으로 밀려나야 하는데, 그 계산이 없어서
스크롤백 열람 중에도 커서가 (틀린 위치에) 그대로 그려질 뻔했다. 뷰포트 범위
밖이면 커서를 그리지 않는 것으로 고쳤다(스크롤백 열람 중엔 실제 커서 위치가
안 보이는 게 일반적인 터미널 동작과도 맞음).

## 검증
- `pageup_reveals_older_scrollback_content`: PageUp 10회로 줄 "1"까지 도달,
  PageDown 10회로 원래 최신 화면(줄 45~50 + 프롬프트)으로 정확히 복귀 확인.
- `cargo test -p syncshell-ui`: 5개 전부 통과.
- `cargo test -p syncshell-core`: 16개 전부 통과(회귀 없음).

## 남은 것 (이 퀘스트의 나머지 범위 — 이번엔 다루지 않음)
- 굵게/밑줄/역상 등 텍스트 속성 렌더링(현재는 전경/배경색 + WIDE_CHAR만 처리)
- 커서 모양(블록/바/언더라인) 및 블링크(현재는 고정 아웃라인 하나뿐)
