플랫폼 독립적인 PTY 레이어를 `core` 크레이트에 구현한다.

## 방침
직접 ConPTY를 래핑하지 말고 **`portable-pty`** (wezterm에서 나온 크레이트)를 사용한다.
Windows는 ConPTY, Unix는 forkpty를 이미 추상화하고 있어 2·3단계 이식 비용이 사라진다.
직접 구현하면 `PROC_THREAD_ATTRIBUTE_PSEUDOCONSOLE_HANDLE` 설정, 핸들 상속 처리 등을
플랫폼마다 다시 해야 하고 호출부도 전부 갈아엎어야 한다.

## 범위
- `portable-pty` 위에 프로젝트용 얇은 `Pty` 인터페이스 정의 (spawn / read / write / resize / kill)
- 기본 셸 결정 로직: Windows=PowerShell, Unix=`$SHELL`. 설정으로 교체 가능
- 입출력을 채널로 브리지 (읽기 스레드 → UI, UI 입력 → 쓰기)
- 셸 종료 감지 및 리소스 정리
- 창/패널 크기 변경 시 PTY 리사이즈 전달

## 메모
- 이 레이어는 UI에 의존하지 않아야 함 — DEV-004 헤드리스 스파이크가 이걸 그대로 재사용한다
- 셸 종료가 감지 안 되면 대개 파이프 핸들 누수. `portable-pty`가 처리하지만 자식 프로세스 handle을 따로 붙들고 있으면 동일 증상 발생

## Test plan
- 셸이 뜨고 명령 출력이 그대로 흘러나오는지 확인
- 리사이즈 후 화면 클리어 시 레이아웃이 깨지지 않는지
- `exit` 시 프로세스가 좀비로 남지 않는지
- (3단계 대비) Unix 빌드에서 동일 코드가 컴파일되는지 — CI에 추가
