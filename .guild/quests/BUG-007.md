Windows에서 한글을 입력하면 조합 중 글자가 잠깐 보였다가 사라지고 확정되지 않는다(2026-10-11 Windows 사용자 확인, 8fdc975·4ab7887). [[DEV-012]]의 IME 조합 입력은 헤드리스 합성 이벤트로만 검증됐고 "실제 IME로 눈으로 확인 필요"로 남아 있었다 — 회귀가 아니라 처음부터 실제 IME에선 안 됐던 것.

## 원인
터미널 위젯이 포커스를 지키려고(architecture 규칙 8) **매 프레임** `response.request_focus()`를 부른다. egui 0.35의 `Memory::request_focus`는 매번 `interrupt_ime()`를 같이 부르고, 그 프레임의 `IMEOutput.should_interrupt_composition = true` → egui-winit이 `set_ime_allowed(false)` 후 `set_ime_allowed(true)`로 IME를 껐다 켜서 진행 중인 조합을 취소한다. 매 프레임 이러니 조합이 확정될 틈이 없다.

[[BUG-006]](키 반복 밀림)도 같은 원인일 수 있다 — 매 프레임 IME 연결을 끊었다 붙이는(ImmAssociateContextEx) 비용.

## 수정
이미 포커스를 가졌으면 `request_focus()`를 부르지 않는다(포커스 잠금 필터는 매 프레임 그대로). 다른 패널을 눌렀다 돌아올 때만 한 번 다시 가져간다.

## 검증
- 자동: `ime_composition_is_not_interrupted_every_frame` — 수정 전 코드에서 6프레임 모두 `should_interrupt_composition=true`(실패), 수정 후 통과
- architecture 규칙 8에 "request_focus는 포커스가 없을 때만" 추가

## Test plan (Windows, 사람 확인)
- 한/영 전환 후 "안녕하세요" 입력 → 조합 글자가 커서 자리에 보이고 스페이스/엔터로 확정되어 셸에 들어가는지
- 한글 키 꾹 눌러 반복, 조합 중 탐색기 클릭했다가 터미널로 돌아와 다시 입력
- [[BUG-006]] 비교: 같은 빌드에서 `SYNCSHELL_IME_AREA_EVERY_EVENT=1`(egui-winit 패치 끔) 실행으로 영문 키 꾹 → 이것만으로도 30회/초·떼면 멈춤이면 egui-winit 패치는 지운다
