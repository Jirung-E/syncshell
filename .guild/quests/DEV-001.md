Rust workspace 초기 구조를 잡고 egui 창이 뜨는 최소 골격을 만든다.

## 범위
- Cargo workspace 루트 생성
- `core` 크레이트: PTY, 파일시스템, 동기화 상태, 경로 추상화 (UI 비의존)
- `ui` 크레이트: eframe/egui 창
- 빌드/실행 확인

## 결정 사항 (확정)
- **스택: Rust + egui/eframe.** WebView 의존 없음, 단일 바이너리, 세 플랫폼 렌더링 동일
- wry(WebView2) 대비 채택 이유:
  - 시동 속도 — WebView2는 별도 브라우저/렌더러 프로세스를 띄워 첫 페인트까지 수백 ms. 구조적이라 튜닝 불가
  - 런타임 — 대량 출력 시 Rust↔JS IPC 직렬화 경계가 병목. egui는 그 경계가 없음. 입력 레이턴시도 유리
  - 메모리 — WebView2 계열 baseline 100MB대 vs egui 수십 MB
  - 3단계 Linux 배포 시 WebKitGTK 의존 문제가 통째로 사라짐
- 감수하는 비용: 터미널 셀 그리드 렌더러와 폰트 스택을 직접 구성해야 함 (DEV-003, DEV-011, DEV-012)
- **UI 코드 착수 전 DEV-004(헤드리스 cwd 스파이크)를 먼저 끝낼 것** — 프로젝트 핵심 가설

## Test plan
- `cargo run` 으로 빈 창이 뜨는지 확인
- 창 리사이즈/닫기 정상 동작
- 콜드 스타트 시간 측정 (기준선 기록용)
