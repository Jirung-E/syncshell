## 보류 — 확인 필요

퀘스트 메모의 "지금 하면 거의 공짜, 나중에 하면 비쌈"이라는 전제는 **이 코드가
아직 안 쓰여 있을 때** 성립한다. 지금은 이미 core 전반(`fsview`, `sync`, `osc7`,
`terminal`, `fsops`)과 ui(`file_panel`, `lib.rs`)에 `PathBuf`/`&Path`가 87곳
퍼져 있고, 전부 예광탄 이후 실사용 검증까지 끝난 핵심 데이터 흐름(동기화,
cwd 추적, 파일 조작)이다. 지금 스코프 인지 타입으로 갈아엎는 건 "지금 하면
공짜"가 아니라 정확히 메모가 경고한 "회수 비용이 큰" 상황이 됐다 — 스펙이
쓰였을 때와 지금 코드베이스 상태가 달라졌다.

빈 껍데기 타입만 새 모듈로 추가하는 것도 고려했지만, 퀘스트 메모 자체가
"핵심은 호출부가 처음부터 이 타입을 쓰게 하는 것"이라고 못 박고 있어서 —
아무 데도 안 쓰는 타입을 추가하는 건 이 퀘스트가 실제로 원하는 걸 달성하지
못하면서 죽은 코드만 늘리는 것이라 판단해 하지 않았다.

WSL(2단계)·Remote(3단계) 계획이 실제로 임박했다면 지금이라도 전체 마이그레이션에
착수하는 게 맞다고 생각하지만, 이건 core 전역을 건드리는 회귀 위험이 있는
결정이라 확인 없이 진행하지 않았다. 진행 여부 알려주시면 바로 착수하겠습니다.
