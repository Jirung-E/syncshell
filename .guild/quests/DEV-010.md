프로젝트별 세션을 저장/복원하고 앱 설정을 관리한다.

## 범위
- 종료 시 상태 저장: 열린 탭, 각 탭의 경로, 분할 레이아웃, 창 위치/크기
- 재실행 시 복원
- 설정: 기본 셸, 폰트/크기, 테마, 동기화 on/off 기본값, 키바인딩
- 설정 UI 또는 최소한 설정 파일 리로드

## 저장 위치

```
~/.syncshell/
├── config.toml    ← 사람이 만지는 것 (셸, 폰트, 테마, 키바인딩)
└── state.toml     ← 앱이 덮어쓰는 것 (탭, 경로, 창 위치/크기)
```

**세 플랫폼 동일 경로.** `directories` 크레이트나 XDG 3분할(config/state/cache)은 쓰지 않는다.
개발 도구는 설정을 찾을 수 있어야 하고 (`~/.cargo`, `~/.ssh`, `~/.gitconfig` 관례),
`%LOCALAPPDATA%\Packages\...\LocalState\` 류로 파묻히면 안 된다.

`SYNCSHELL_HOME` 환경변수로 위치 오버라이드 가능 (포터블 실행·테스트용).

### 파일을 둘로 나누는 이유
git 관리 때문이 아니다. 실질적인 이유는:
- **설정은 사람이 쓰고 상태는 앱이 매 종료마다 덮어쓴다.** 한 파일이면 앱이 파일을
  통째로 재작성하면서 사용자 주석과 포맷을 날린다
- 세션 저장 중 크래시가 설정까지 손상시키지 않음 (blast radius 분리)
- "창이 화면 밖으로 나갔다" → `state.toml`만 지우면 복구. 설정은 보존

`cache/`는 만들지 않는다. 1단계에 영속 캐시가 필요한지 불확실하고(글리프 아틀라스는
메모리로 충분), 실제로 필요해질 때 추가하면 된다.

### eframe 자체 persistence를 끌 것 (중요)
eframe에는 내장 persistence 기능이 있고, 활성화돼 있으면 `directories` 크레이트로
플랫폼 경로를 잡아 창 위치 등을 **우리가 모르는 사이에** 저장한다.
그대로 두면 `%APPDATA%\...` 에 두 번째 저장 위치가 생긴다 — 방금 없애기로 한 바로 그 경로에.

- `persistence` cargo feature를 켜지 않거나, `NativeOptions`의 관련 옵션을 끌 것
- 창 위치/크기 저장은 우리 `state.toml`이 단독으로 책임진다
- 구현 후 실제로 `%APPDATA%` / `~/Library/Application Support` 아래에 아무것도
  생기지 않는지 눈으로 확인할 것

### Windows 주의
`.` 로 시작하는 폴더는 Windows에서 **자동으로 숨겨지지 않는다** (숨김 속성은 이름과 별개).
syncshell 자체가 파일 탐색기라 자기가 만든 폴더가 자기 화면에 노출된다.
디렉터리 생성 시 `FILE_ATTRIBUTE_HIDDEN` 을 세팅할 것.

## 메모
- **경로 해석은 `core`의 함수 하나로 격리한다.** 호출부가 경로를 직접 조립하지 않게 할 것.
  그래야 나중에 XDG 지원(리눅스 패키징 시 메인테이너 요구 등)이 필요해져도 싸게 바뀐다
- 세션 복원 시 존재하지 않는 경로는 조용히 상위 폴더로 폴백
- 설정 파일 손상 시 기본값으로 복구하고 손상본은 `.bak` 로 남길 것
- `state.toml` 쓰기는 원자적으로 (임시 파일 → rename)

## Test plan
- 탭 3개 + 분할 상태로 종료 후 재실행 → 동일 레이아웃 복원
- 저장된 경로가 삭제된 상태에서 재실행 시 크래시 없음
- `config.toml`에 주석을 달아두고 앱을 여러 번 껐다 켜도 주석이 보존되는지
- 설정 파일 손상 시 기본값으로 복구
- `SYNCSHELL_HOME` 지정 시 해당 위치를 사용하는지
- Windows에서 `~/.syncshell` 이 탐색기에 숨김으로 표시되는지
- **앱을 켰다 끈 뒤 `~/.syncshell/` (또는 `SYNCSHELL_HOME`) 외의 위치에 파일이
  전혀 생기지 않는지 확인** — eframe persistence 누수 검증
