Windows(그리고 Linux)도 macOS처럼 커스텀 타이틀바로 맞춘다 — OS가 달라도 기본 모습은 같아야 한다(2026-10-03 사용자 결정). [[DEV-014]]는 macOS만 구현하고 Windows는 검증 수단이 없어 보류했었다.

## 범위
- OS 기본 타이틀바를 끄고(`with_decorations(false)`) 탭 바가 그 자리를 대신
- 탭 바 오른쪽 끝에 창 버튼(최소화 / 최대화·복원 / 닫기) — Windows 관례 크기(46px), 닫기 호버는 빨강
- 탭 바 빈 곳 드래그 = 창 이동, 더블클릭 = 최대화 토글 (macOS도 같은 동작)
- 창 가장자리 드래그로 크기 조절 — winit은 테두리 없는 창의 비클라이언트 영역을 전부 앱 영역으로 덮어서 OS 기본 가장자리 크기 조절이 없다 → 가장자리 몇 px에서 직접 `BeginResize`

## 범위 밖 / 알려진 차이
- Windows 11 최대화 버튼 호버 시 뜨는 스냅 레이아웃 메뉴(WM_NCHITTEST HTMAXBUTTON 필요, raw 창 핸들 코드) — Win+Z, 화면 가장자리로 끌어 스냅은 그대로 동작(winit이 WS_CAPTION 유지)

## 구현 메모
- `CUSTOM_WINDOW_CONTROLS = cfg!(not(target_os = "macos"))` 상수 — `#[cfg]` 대신 상수라 macOS에서도 Windows 쪽 코드가 컴파일된다
- 창 버튼: `chrome::window_controls` (닫기 호버 #C42B1C)
- 탭 바 빈 곳: 드래그 → `StartDrag`, 더블클릭 → 최대화 토글 (macOS 포함)
- 가장자리 5px(모서리 10px)에서 커서 변경 + `BeginResize`, 최대화/전체화면 땐 끔
- macOS에서 `cargo check --target x86_64-pc-windows-msvc --tests` 통과 확인. 실제 Windows 실행은 아직

## Test plan
- 자동: 가장자리·모서리 판정
- 사람 확인 (Windows):
  - OS 기본 타이틀바가 없고 탭 바가 맨 위에 있는지, 창 그림자가 있는지
  - 최소화 / 최대화·복원 / 닫기 버튼, 닫기 호버 빨강
  - 탭 바 빈 곳 끌어 이동, 더블클릭 최대화, 화면 위쪽 가장자리로 끌어 스냅, Win+화살표
  - 네 변·네 모서리 끌어 크기 조절(커서 모양), 최대화 상태에선 가장자리 반응 없음
  - 탭·+ 버튼·세그먼트 버튼 클릭이 창 이동으로 먹히지 않는지
- 사람 확인 (macOS): 탭 바 빈 곳 드래그·더블클릭이 기존처럼 동작하는지
