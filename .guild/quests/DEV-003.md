터미널 상태머신을 연동하고 egui 위에 셀 그리드 렌더러를 구현한다.

## 방침
VT 파서·그리드·스크롤백을 직접 짜지 않는다. **`alacritty_terminal`** 크레이트가
ANSI 파싱, 셀 그리드, 스크롤백, 커서 상태를 이미 갖고 있으므로 이것을 상태 소스로 쓰고,
egui 페인터로 그리는 부분만 구현한다.

## 범위
- `alacritty_terminal` 연동: PTY 바이트 스트림 → Term 상태 갱신
- egui 셀 그리드 렌더러: 셀 단위 글리프 + 전경/배경색 + 속성(볼드/언더라인/역상)
- 커서 렌더링 (블록/바/언더라인, 블링크)
- 스크롤백 스크롤, 휠/키보드 스크롤
- 키 입력 → PTY 바이트 인코딩 (특수키, 修飾키 조합, 애플리케이션 커서 모드)
- 다시 그릴 필요가 있을 때만 repaint 요청 (유휴 시 CPU 0에 가깝게)

## 분리된 항목
- 폰트 스택 / CJK 폭 처리 → 별도 퀘스트
- 선택·복사·IME → 별도 퀘스트

## 메모
- egui는 immediate mode지만 eframe은 입력/명시적 요청이 있을 때만 repaint. 출력 스트림이
  들어올 때 `request_repaint()`를 호출하는 구조로. 무조건 60fps로 돌리면 배터리를 먹는다
- 대량 출력 시 프레임당 여러 청크를 모아 Term에 밀어넣고 한 번 그릴 것

## Test plan
- 대화형 명령(vim, python REPL 등) 정상 동작
- 대량 출력(`cargo build`, 대용량 파일 cat) 시 UI가 멈추지 않음
- 유휴 상태 CPU 사용률 확인
- 스크롤백 경계에서 렌더링 깨짐 없음
